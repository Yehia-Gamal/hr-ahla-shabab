# FIX_REPORT_095 — KPI Workflow Polish + UI/Nav Refinement

## الهدف
تطبيق مسار KPI الصحيح بدون السماح للمدير بإنشاء تقييم من البداية:

1. الموظف يقيّم نفسه ويحفظ النموذج.
2. النموذج ينتقل تلقائيًا للمدير المباشر.
3. المدير يؤكد أو يعدل النسب ثم يسلّم HR.
4. HR يكمل بنود الحضور والصلاة وحلقة الشيخ وليد.
5. السكرتير التنفيذي/التقني يراجع النماذج والنسب.
6. المدير التنفيذي يعتمد النتيجة النهائية.

## التعديلات الرئيسية
- ضبط واجهة الموظف KPI لتستخدم `SELF_SUBMITTED` بدل قيمة غير قياسية.
- إصلاح احتساب سلايدر الموظف: النسبة المئوية تتحول الآن إلى درجات فعلية حسب الوزن.
- منع المدير من إنشاء تقييم من الصفر في طبقة API المحلية.
- منع HR من استلام نموذج قبل اعتماد المدير.
- منع السكرتير/التقني من استلام نموذج قبل مراجعة HR.
- منع الاعتماد التنفيذي قبل مراجعة السكرتير التنفيذي.
- تطبيق نفس منطق المراحل على Supabase API قدر الإمكان من الواجهة.
- تحسين شاشة KPI في لوحة HR/الإدارة بحيث تعرض فقط النماذج الجاهزة للمرحلة الحالية.
- تحسين ألوان حالات KPI والنافبار وكروت التقييم.
